# 24_offer_evaluation_scorecard

## Purpose

This document provides a practical system for evaluating, negotiating, accepting or rejecting job offers.

It is designed for a Colombia-based Real-Time 3D Developer / Unity Technical Artist targeting international remote work, contractor/B2B roles, Unity WebGL, technical visualization, simulation, digital twin, XR-adjacent work and Python tooling as a secondary route.

The system is not legal, tax or immigration advice. Any contract, tax setup or relocation decision should be reviewed with qualified professionals.

---

# 1. Core decision rule

Do not accept an offer only because it is international.

An offer is strategically useful only if it satisfies most of these conditions:

1. compensation is above the minimum threshold;
2. net income is acceptable after taxes, fees and social security;
3. the role strengthens the real-time 3D / Unity / technical visualization path;
4. contract terms are clear;
5. payment risk is controlled;
6. IP and exclusivity terms are reasonable;
7. remote work from Colombia is legally and operationally feasible;
8. the role does not create major strategic dilution;
9. the work can build toward USD 3k–6k/month over 12–24 months.

# 2. Offer categories

## Offer type classification

| Type | Description | Default stance |
|---|---|---|
| Strategic offer | Strong role fit + acceptable compensation + safe structure | Consider strongly |
| Cashflow offer | Pays acceptably but weak strategic fit | Accept only if needed |
| Portfolio leverage offer | Lower pay but strong proof/project value | Consider selectively |
| Risky offer | Unclear pay, scope or legal terms | Renegotiate or reject |
| Dilution offer | Pulls profile away from target path | Usually reject |
| Exploitative offer | Free labor, vague equity, abusive terms | Reject |

## Role-fit classification

| Role | Strategic value |
|---|---|
| Real-Time 3D / Unity | High |
| Unity WebGL / Interactive 3D | High |
| Technical Visualization / Digital Twin | High |
| Unity Technical Artist | High if runtime/optimization/tools |
| XR / Simulation | Medium-high |
| Tools / Python Automation | Medium |
| Full-stack | Low-medium |
| 3D Artist / Generalist | Low unless technical |
| Generic web design | Low |
| AI hype role without real scope | Risky |

# 3. Offer scorecard

Score each criterion from 1 to 5.

Then multiply by weight.

## Main scorecard

| Criterion | Weight | Score |
|---|---:|---:|
| Gross compensation | 15 | 1–5 |
| Estimated net compensation | 15 | 1–5 |
| Role fit | 20 | 1–5 |
| Portfolio leverage | 15 | 1–5 |
| Contract clarity | 10 | 1–5 |
| Payment reliability | 10 | 1–5 |
| Remote feasibility | 10 | 1–5 |
| Growth / learning ROI | 5 | 1–5 |
| Total | 100 | — |

## Interpretation

| Total score | Decision |
|---:|---|
| 85–100 | Strong accept / negotiate upward |
| 70–84 | Acceptable if no hidden risks |
| 55–69 | Renegotiate or accept only for cashflow |
| 40–54 | Usually reject |
| Under 40 | Reject |

## Automatic override

Reject even if score is high if there is:

- no written contract;
- unclear payment terms;
- broad unpaid test;
- abusive IP assignment;
- illegal or impossible work authorization assumption;
- non-payment history;
- requirement to misrepresent status;
- broad non-compete;
- no clarity on contractor vs employee;
- request for free production work.

|---|---|

| USD 2k–3k | Viable early offer |

## Important distinction

Always separate:

```text
Gross compensation
Net compensation
Cashflow timing
Long-term value
```

A high gross offer with delayed, risky or non-compliant payment can be worse than a lower but stable offer.

# 6. Gross-to-net checklist

Before accepting a contractor offer, estimate:

| Item | Question |
|---|---|
| Gross monthly | What is the nominal amount? |
| Currency | USD, EUR, COP or other? |
| Payment fees | Wise, Payoneer, PayPal, SWIFT, bank spread? |
| Conversion loss | What exchange rate applies? |
| Taxes | What must be reserved? |
| Social security | EPS, pension, ARL? |
| Accountant | Monthly cost? |
| Software/equipment | Who pays? |
| Vacation | Unpaid or paid? |
| Sick days | Unpaid or paid? |
| Payment delay | 7, 15, 30, 45, 60 days? |
| Contract termination | How much notice? |

## Net estimate formula

Use a conservative model:

```text
Estimated net = gross
- platform/payment fees
- currency conversion loss
- tax reserve
- social security
- accountant/admin costs
- unpaid time reserve
- software/equipment costs
```

## Required reserve

For contractor income, keep reserves for:

- taxes;
- social security;
- slow payment;
- contract termination;
- equipment failure;
- medical/emergency buffer;
- unpaid vacation.

# 8. Contractor vs employee evaluation

## Contractor advantages

| Advantage | Meaning |
|---|---|
| International access | Easier for foreign companies |
| Higher gross potential | Often better than local salary |
| Flexibility | Can work with global clients |
| Portfolio control | Project-based leverage |
| Faster entry | No sponsorship needed |

## Contractor disadvantages

| Disadvantage | Meaning |
|---|---|
| No benefits | No paid vacation unless negotiated |
| Tax/admin burden | Must manage compliance |
| Payment risk | Late or non-payment possible |
| No job security | Contract can end quickly |
| Misclassification risk | If relationship is employee-like |
| Equipment/software | Often self-funded |

## Employee advantages

| Advantage | Meaning |
|---|---|
| Stability | More predictable |
| Benefits | Health, vacation, severance depending on jurisdiction |
| Lower admin | Payroll handled |
| Team integration | Better mentorship |
| Career signaling | Stronger formal experience |

## Employee disadvantages

| Disadvantage | Meaning |
|---|---|
| Lower flexibility | Less control |
| Authorization barriers | Foreign employment may require local setup |
| Lower local salary | Colombia salaries may be lower |
| EOR dependency | Employer must support structure |

## EOR evaluation

EOR is useful if:

- company wants employee relationship;
- role is long-term;
- compensation justifies EOR cost;
- employer is willing to pay platform fees;
- compliance matters.

EOR is less likely for:

- small studios;
- short contracts;
- low-budget roles;
- trial projects.

# 9. Contract terms checklist

## Must be clear

| Term | Required clarity |
|---|---|
| Parties | Legal names |
| Role | Scope and title |
| Start date | Exact |
| End date | If fixed-term |
| Compensation | Amount and currency |
| Payment schedule | Weekly/monthly/milestones |
| Payment method | Bank/Wise/Payoneer/etc. |
| Late payment | Consequence or remedy |
| Work hours | Expected availability |
| Time zone | Required overlap |
| Deliverables | Defined |
| IP ownership | Clear |
| Confidentiality | Reasonable |
| Exclusivity | Limited or absent |
| Non-compete | Avoid broad terms |
| Termination | Notice period |
| Dispute law | Jurisdiction |
| Equipment/software | Who pays |
| Taxes | Contractor responsibility if B2B |
| Data/security | Reasonable requirements |

## Dangerous contract terms

| Clause | Risk |
|---|---|
| Broad non-compete | Blocks future work |
| Broad exclusivity | Prevents other clients |
| Work-for-hire over all past/future work | IP abuse |
| Payment only after client approval | Cashflow risk |
| Unlimited unpaid revisions | Scope creep |
| No termination notice | Instability |
| No late-payment remedy | Non-payment risk |
| Mandatory unpaid trial | Exploitation |
| Confusing employee/contractor language | Misclassification |
| Jurisdiction impossible to enforce | Legal risk |

# 10. Take-home test evaluation

## Acceptable test

A take-home test is acceptable if:

- it is small;
- it has a clear time limit;
- it is relevant to the role;
- it does not produce usable client work;
- it has clear evaluation criteria;
- it does not require unpaid multi-day labor;
- IP terms are clear;
- the company is credible.

## Reasonable test examples

| Role | Reasonable test |
|---|---|
| Unity Developer | Small interaction prototype |
| Technical Artist | Shader/material or optimization task |
| WebGL | Small build/performance task |
| Tools | Small editor script |
| Python Automation | Small workflow script |
| Digital Twin | Conceptual architecture task |

## Unreasonable test examples

| Test | Reason |
|---|---|
| Full feature implementation | Free labor |
| Client-ready prototype | Exploitation |
| Multi-day unpaid build | Excessive |
| Unclear ownership | IP risk |
| No feedback | Low value |
| Requires private assets without agreement | Legal risk |
| Looks like production backlog | Red flag |

## Test negotiation script

```text
I’m open to a focused technical exercise. To keep the scope reasonable, could we define an expected time limit and clarify whether the test is only for evaluation and not production use?
```

## Test refusal script

```text
I’m not comfortable completing a large unpaid production-style task. I would be open to a smaller scoped exercise, a paid test, a portfolio walkthrough, or a live technical discussion instead.
```

# 11. Red flags

## Critical red flags

Reject or pause if:

- no written contract;
- payment terms unclear;
- company refuses to define scope;
- asks for free production work;
- broad non-compete;
- broad IP claim over unrelated work;
- payment only after client approval;
- “remote” but requires unavailable work authorization;
- asks to misrepresent legal status;
- insists on employee-like control under contractor structure;
- salary below minimum with no strategic upside;
- company has public non-payment complaints.

## Moderate red flags

Negotiate or clarify if:

- vague role title;
- unclear reporting structure;
- unclear timezone expectations;
- no onboarding process;
- vague “startup equity” promises;
- unclear tool/software reimbursement;
- all communication only by chat;
- no technical interviewer;
- constant urgency;
- trial period without clear compensation.

## Low-level warning signs

Monitor if:

- delayed recruiter responses;
- overly broad job description;
- role mixes too many unrelated skills;
- no clear product/project;
- old job posting;
- compensation hidden until late;
- vague remote policy.

# 12. Offer-specific questions

## Compensation

Ask:

```text
What is the gross compensation?
What currency is used?
Is payment monthly, biweekly or milestone-based?
What are the payment terms?
Are there late-payment protections?
Is compensation fixed, hourly or retainer-based?
```

## Contractor structure

Ask:

```text
Is this B2B/contractor, employee, EOR or freelance?
Who is the legal contracting entity?
What invoices or tax forms are required?
Is there a required platform?
Is there a trial period?
```

## Scope

Ask:

```text
What are the first 30/60/90 day deliverables?
What does success look like?
What is the expected weekly availability?
How much meeting time is expected?
What timezone overlap is required?
```

## IP and confidentiality

Ask:

```text
Who owns the deliverables?
Does IP assignment apply only to paid work?
Are personal/portfolio projects excluded?
Can I show non-confidential work in my portfolio?
Are there confidentiality restrictions?
```

## Technical role

Ask:

```text
What engine/platform is used?
What Unity version and render pipeline?
Is WebGL/XR/mobile/desktop the target?
How is profiling handled?
How is asset optimization handled?
Will I write production C#?
Will I work with artists/designers/engineers?
```

Accept if:

- compensation meets target;
- contract is clear;
- role fit is strong;
- remote structure is feasible;
- payment risk is low;
- no major red flags;

## Conditional accept

Accept if:

- score 65–80;
- compensation is acceptable;
- role fit is useful;
- risks can be negotiated;
- cashflow or formal experience value is meaningful.

## Reject

Reject if:

- score below 55;
- compensation below minimum;
- role dilutes profile severely;
- payment risk is high;
- contract is unclear;
- unpaid work is excessive;
- authorization assumptions are false;
- IP/exclusivity terms are abusive.

# 14. Negotiation strategy

## General rule

Negotiate based on structure, not just salary.

Consider:

- rate;
- hours;
- payment timing;
- trial period;
- deliverables;
- IP;
- exclusivity;
- scope;
- timezone;
- renewal terms;
- portfolio usage;
- software/equipment.

## If compensation is low but role is strong

Negotiate:

```text
higher rate after trial;
shorter trial period;
reduced hours;
clear portfolio permission;
defined scope;
milestone payment;
review after 30/60 days.
```

## If role is good but contractor risk is high

Negotiate:

```text
advance payment;
short payment cycle;
written contract;
clear termination notice;
paid test;
no broad exclusivity;
limited IP assignment.
```

## If company wants full-time contractor

Clarify:

```text
expected hours;
exclusivity;
benefits;
paid time off;
tools;
whether relationship is truly contractor;
tax responsibility;
EOR possibility.
```

# 15. Negotiation scripts

## Ask for higher compensation

```text
Based on the scope, expected availability and the technical requirements around Unity, WebGL and real-time 3D visualization, I would be more comfortable at [target range].

If that is above the current budget, we could also discuss adjusting scope, hours, trial length or review timing.
```

## Ask for paid test

```text
I’m open to a technical evaluation. Since the task appears close to production work and may take several hours, would you be open to making it a paid test or reducing the scope to a shorter evaluation exercise?
```

## Ask for clearer scope

```text
Before accepting, I would like to clarify the first deliverables, expected weekly availability, decision-making process and success criteria for the first 30 days.
```

## Ask about IP

```text
Could you clarify whether IP assignment applies only to paid deliverables created under this contract, and whether my previous work, portfolio projects and independent tools are excluded?
```

## Ask about contractor structure

```text
Since I am based in Colombia, I want to confirm whether this would be structured as an independent contractor/B2B agreement, EOR employment or another setup.
```

## Decline politely

```text
Thank you for the offer. After reviewing the compensation, scope and contract structure, I do not think this is the right fit at this stage.

I appreciate the opportunity and would be open to reconnecting in the future if there is a role with clearer alignment around Unity, real-time 3D or technical visualization.
```

# 22. Final recommendation

The safest decision model is:

```text
Do not optimize only for the first paycheck.
Optimize for the intersection of compensation, contract safety and real-time 3D positioning.
```

The ideal first international offer is not necessarily the highest gross number.

The best offer is the one that:

1. pays enough;
2. is legally and operationally clear;
3. strengthens the Unity / real-time 3D / technical visualization path;
4. creates credible professional experience;
5. does not trap the profile in unrelated work;
6. can become a stepping stone toward USD 3k–6k/month.
