# 17_cv_base_and_role_variants

## Purpose

This document converts the approved career strategy into CV-ready material.

It includes:

- a base one-page CV structure;
- role-specific CV variants;
- reusable bullet banks;
- project descriptions;
- skills blocks;
- education wording;
- training/course wording;
- language and work-authorization wording;
- claims to avoid;
- editing rules.

This is not the final designed PDF CV. It is the source text for producing one-page ATS-friendly resumes.

---

# 1. CV positioning rules

## Core identity

Use this as the main professional identity:

```text
Real-Time 3D Developer / Unity Technical Artist
```

Expanded version:

```text
Real-Time 3D Developer / Unity Technical Artist focused on interactive technical visualization, CAD-to-realtime optimization, and Unity WebGL deployment.
```

## Primary CV target families

Use separate variants for:

1. Real-Time 3D / Unity Developer.
2. Technical Visualization / Digital Twin / Simulation Developer.
3. Unity WebGL / Interactive 3D Developer.
4. Unity Technical Artist.
5. Tools / Python Automation Developer.

## Do not use one generic CV for every job

The base CV should be adapted per role family. The same facts can be reorganized, but the claims must remain consistent.

## Critical claim discipline

Do not claim:

- Senior Technical Artist.
- EU work authorization now.
- German residence now.
- Portuguese passport already issued.
- Unity certification if not obtained.
- Rebelway / CG Cookie / Alive certification if no certificate exists.
- Production AI engineer.
- Enterprise AI platform developer.
- Commercially shipped Unity product unless true.
- Full-stack specialist as primary identity.

# 14. CV length and formatting rules

## One-page target

The default CV should be one page.

If needed, use a two-page technical resume only for:

- highly technical roles;
- technical artist roles requiring detailed portfolio breakdown;
- senior reviewers who explicitly ask for detail.

## Recommended section order

```text
Header
Professional Summary
Technical Skills
Selected Projects
Experience
Education
Training
Languages / Availability
```

## ATS formatting rules

Use:

- plain section headers;
- no icons;
- no columns if ATS compatibility is critical;
- simple bullets;
- standard file name;
- PDF for submission;
- DOCX only if requested.

File naming:

```text
Alexander_Woodcock_RealTime3D_Unity_CV.pdf
Alexander_Woodcock_Technical_Visualization_CV.pdf
Alexander_Woodcock_Unity_WebGL_CV.pdf
Alexander_Woodcock_Tools_Python_CV.pdf
```

# 16. Red-flag edits to avoid

Do not:

- add too many unrelated technologies;
- list every course;
- list every repo;
- exaggerate years of experience;
- overemphasize full-stack;
- overemphasize AI tooling;
- overemphasize character art;
- describe unfinished projects as complete;
- hide the fact that TwinSight is academic;
- make the CV read like a thesis abstract;
- use dense paragraphs;
- use vague phrases like “passionate,” “dynamic,” or “hardworking.”
