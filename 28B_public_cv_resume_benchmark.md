## 4. Benchmark patterns

### 4.1 Strong CVs use a narrow headline

The strongest examples do not use broad titles like “creative developer” or “3D generalist” as the main positioning. They use direct role labels:

```text
Technical Artist
Senior Technical Artist
Senior Unity Developer
XR Developer
Unity Expert
3D Visualization Artist
```

Alexander should use a narrow headline, not a broad identity label.

Recommended primary headline:

```text
Real-Time 3D Developer / Unity Technical Artist
```

Alternative headline for Unity-heavy applications:

```text
Unity WebGL Developer focused on Technical Visualization
```

Alternative headline for 3D/technical art applications:

```text
Unity Technical Artist focused on CAD-to-Realtime Visualization
```

---

### 4.2 Strong CVs show proof before personality

The best examples prioritize evidence:

```text
role → project → tools → responsibility → result
```

Weak examples rely on generic traits:

```text
passionate
creative
hard-working
team player
problem solver
```

Alexander’s CV should minimize soft claims and increase visible proof.

---

### 4.3 Strong CVs expose project scale

The best CVs include scale markers such as:

```text
5 shipped titles
40,000 downloads
150k+ downloads
500k users
100+ hours saved
2,500+ assets
33 ms frame-time budget
4 GB memory budget
```

Alexander should not invent metrics. He should add measured or verifiable project metrics once the TwinSight evaluation is complete.

Usable current metrics from the thesis context:

```text
28 canonical research parts
30 scene nodes
257 technical elements
Unity WebGL target
30 FPS target = 33 ms frame-time budget
CAD-to-realtime pipeline
mobile-first interface
```

Metrics still pending:

```text
actual FPS
actual frame time
load time
memory use
SUS score
NASA-TLX Raw score
participant count
```

---

### 4.4 Strong CVs organize technical skills by function

The better examples group skills by category. They do not dump every tool into one long list.

Recommended skill grouping for Alexander:

```text
Real-time development
3D production pipeline
Technical visualization
Web deployment
Automation and tooling
Version control
```

Bad pattern to avoid:

```text
Unity, Blender, Photoshop, Python, WebGL, Substance, Git, C#, AI, UX, UI, AR, VR, etc.
```

That kind of list dilutes positioning.

---

### 4.5 Strong CVs connect portfolio and resume

The strongest examples include links to one or more of:

```text
portfolio
GitHub
project pages
PDF resume
LinkedIn
live demos
store pages
itch.io
```

Alexander’s CV should link directly to:

```text
portfolio site
TwinSight live demo
TwinSight GitHub repository
TwinSight case study
LinkedIn
ArtStation or 3D portfolio
```

The CV should not depend on the reader searching manually.

### 6.4 TwinSight X500 section

Recommended section title:

```text
Selected Technical Project — TwinSight X500
```

Recommended role line:

```text
Unity WebGL Technical Visualization Prototype | Thesis Project
```

Recommended bullets:

```text
- Designed and developed a Unity WebGL prototype for inspecting the assembly of a Holybro X500 V2 drone through interactive 3D visualization.
- Built a CAD-to-realtime pipeline using Blender, mesh cleanup, modular fasteners, UV preparation, texture baking, and Unity optimization.
- Structured the model into 28 canonical research parts, 30 scene nodes, and 257 technical elements for inspection and interaction.
- Designed a mobile-first interface with Unity UI Toolkit for part selection, isolation, transparency, and assembly understanding.
- Prepared technical evaluation around frame time, load time, memory use, usability, perceived workload, and qualitative feedback.
```

Do not claim final performance metrics until measured.

When measured, add one bullet like:

```text
- Achieved [X] FPS / [Y] ms frame time / [Z] MB memory use in WebGL testing on [device/browser].
```
