## 2. Objetivo del benchmark

Este módulo analiza cómo se presentan públicamente proyectos comparables o parcialmente comparables a **TwinSight X500**, especialmente en video.

El objetivo no es copiar contenido visual, sino extraer patrones de presentación para diseñar un demo video profesional de 60–120 segundos para un perfil de:

```text
Real-Time 3D Developer / Unity Technical Artist
Unity WebGL · CAD-to-Realtime · Technical Visualization · Interactive 3D
```

---

## 3. Perfil de referencia: TwinSight X500

TwinSight X500 debe presentarse como:

```text
A Unity WebGL technical visualization prototype for drone assembly inspection.
```

La demo debe comunicar:

- problema de documentación 2D;
- solución en 3D interactivo;
- selección de componentes;
- exploded view;
- clipping / cross-section;
- modos visuales;
- UI técnica;
- pipeline CAD-to-realtime;
- optimización;
- validación con usuarios;
- propiedad técnica honesta, incluyendo AI-assisted implementation si se menciona.

# 6. Benchmark: demo examples

## 6.1 Personal technical reels

| Demo | Role target | Duration | Relevance |
|---|---|---:|---|
| Robin Cai 2025 Visual Effects & Technical Art Demoreel | Technical Artist | 1:42 | Medium |
| Unity Developer Demo Reel 2025 | Unity / WebGL Developer | 1:17 | High |

### Notes

Personal reels tend to:

- start fast;
- show work immediately;
- use short clips;
- rely on captions or title cards;
- avoid long explanations;
- show breadth of skill;
- end with name/contact/portfolio.

### Application to TwinSight

TwinSight should not behave like a general art reel. It should be closer to a **technical product demo** with reel pacing.

Use:

```text
fast visual proof + captions + metrics + short technical breakdown
```

Do not use:

```text
music-only montage with unclear functionality
```

# 10. Caption system

## 10.1 Caption style

Use short captions, not paragraphs.

Good:

```text
Component selection + technical panel
```

Bad:

```text
This system allows the user to select different drone components and view the associated information while navigating the interface.
```

Unity WebGL technical visualization

# 11. Voiceover recommendation

## Main recommendation

Use **captions + music only** for the public reel.

Add voiceover only for the long technical breakdown.

## Reason

Recruiters often skim videos silently. Captions are safer.

## If using voiceover

Keep it technical and restrained.

Example:

```text
TwinSight X500 is a Unity WebGL technical visualization prototype for drone assembly inspection. It converts CAD-derived assets into an optimized browser-based viewer with component selection, exploded view, cross-section tools, technical panels, and validation through SUS and NASA-TLX.
```

# 13. Editing rules

## 13.1 Must do

- show final output in first 5 seconds;
- use captions on every feature;
- keep shots short;
- show interaction, not just orbit shots;
- include metrics;
- include stack;
- include one clear end card;
- export cleanly at 1080p minimum;
- use consistent typography;
- avoid excessive transitions.

## 13.2 Must avoid

- long intro logos;
- slow cinematic-only orbit;
- unclear UI text;
- music louder than explanation;
- too many effects;
- pretending it is a shipped commercial product;
- hiding that it is an academic/portfolio prototype;
- overusing “AI” in the main reel;
- adding unimplemented XR/IoT/WebAR features.
