# 1. Purpose

This module defines the weekly execution system for Alexander’s job-search roadmap.

The goal is not to maximize raw application volume. The goal is to run a controlled system that balances:

```text
portfolio proof
targeted applications
market feedback
follow-ups
interview preparation
material iteration
```

Current strategic position:

```text
Unity WebGL / Real-Time 3D Developer
Technical Visualization + Technical Art
XR / Simulation-adjacent portfolio
C# + shaders + optimization + 3D pipeline
```

---

# 2. Operating principle

## 2.1 Main rule

```text
Proof quality first, application volume second.
```

Because the current market evidence shows:

```text
- many roles are senior;
- portfolio/reel proof matters;
- technical-art/rendering proof matters;
- LATAM remote exists but is narrow;
- WebGL/technical visualization is a differentiator;
- generic Unity roles are competitive and often game/mobile-heavy.
```

## 2.2 Weekly loop

```text
1. Search
2. Score
3. Tailor
4. Apply
5. Follow up
6. Track
7. Review
8. Improve materials
```

This loop repeats weekly.

```text

[ ] Reject obvious mismatches.
[ ] Score remaining roles.
[ ] Select 5–12 target applications.
[ ] Assign CV variant.
[ ] Assign portfolio/GitHub links.
```

```text

Real-Time 3D Developer remote
Interactive 3D Developer remote
```

```text
Goal:
```

# 9. Cover note workflow

## 9.1 When to write a note

Write a note only if:

```text
the platform has a field,
the fit is Priority A/B,
and the note can mention specific overlap.
```

## 9.2 Note length

```text
50–120 words
```

## 9.3 Note formula

```text
1. Role fit
2. TwinSight evidence
3. Stack match
4. Remote/contractor availability if relevant
```

## 9.4 Example — Unity WebGL

```text
I’m applying because this role aligns closely with my Unity WebGL technical visualization work. My flagship project, TwinSight X500, is a browser-based 3D inspection prototype for drone assembly, built with Unity, C#, WebGL, URP, UI Toolkit and Blender. It includes component selection, exploded view, clipping tools, visual modes, CAD-to-realtime optimization and usability/workload evaluation.
```

## 9.5 Example — LATAM remote Unity

```text
I’m based in Colombia and available for remote LATAM or international contractor work. My strongest Unity project is TwinSight X500, a WebGL technical visualization prototype with C#, URP, UI Toolkit, Blender optimization, component interaction and usability evaluation.
```

# 10. Follow-up system

## 10.1 Follow-up timing

| Situation | Follow-up |
|---|---|
| application submitted | after 5–7 business days |
| recruiter viewed profile | within 24–48 hours |
| interview completed | within 24 hours |
| technical test submitted | within 24 hours |
| no response after follow-up | one final follow-up after 7 days |

## 10.2 Follow-up template

```text
Hi [Name],

I wanted to follow up on my application for [Role]. I’m especially interested because the role aligns with my Unity WebGL and technical visualization work.

My flagship project, TwinSight X500, is a browser-based Unity prototype for drone assembly inspection, with component selection, exploded view, clipping tools, visual modes and CAD-to-realtime optimization.

Portfolio: [link]
GitHub: [link]

Best,
Alexander
```

## 10.3 Follow-up rule

Do not follow up more than twice unless there is active conversation.

# 13. Feedback loop

## 13.1 If no responses after 20 applications

Check:

```text
[ ] portfolio link visible?
[ ] demo video strong?
[ ] CV headline too broad?
[ ] applying to too-senior roles?
[ ] remote eligibility unclear?
[ ] cover note weak?
[ ] GitHub README incomplete?
```

## 13.2 If responses but no interviews

Check:

```text
[ ] CV experience gap too visible?
[ ] project description not business-relevant?
[ ] salary expectation mismatch?
[ ] English profile weak?
[ ] not enough commercial framing?
```

## 13.3 If interviews but no offers

Check:

```text
[ ] interview defense weak?
[ ] AI-use answer unclear?
[ ] technical depth not defended?
[ ] coding test gap?
[ ] shader/rendering gap?
[ ] remote contractor concerns?
```

# 17. Interview preparation loop

## 17.1 Weekly rehearsal

Once per week, rehearse:

```text
Tell me about TwinSight.
Why Unity WebGL?
How did you optimize CAD?
What was your role?
How did you use AI?
Is it a digital twin?
What would you improve?
Why should we hire you despite limited formal experience?
```

## 17.2 Answer quality criteria

Good answers are:

```text
specific
technical
honest
short
evidence-backed
not defensive
```

Bad answers are:

```text
vague
overexplaining
self-deprecating
overclaiming
too academic
```

# 21. Weekly done definition

A week is successful if:

```text
[ ] at least 5 good roles were scored
[ ] at least 3–8 applications were sent, depending on readiness
[ ] tracker is updated
[ ] follow-ups were sent where due
[ ] one material asset improved
[ ] one weekly review was written
[ ] next week focus is defined
```

A week is not successful if:

```text
many roles were browsed but none were tracked
applications were sent without scoring
materials were not improved
follow-ups were forgotten
no learning was extracted
```
