TwinSight X500

Unity WebGL technical visualization for drone assembly inspection.

A browser-based 3D inspection prototype that turns CAD-derived drone assets into an optimized Unity WebGL experience with selection, exploded views, clipping, visual modes, technical UI and formative usability testing.

Problem

2D documentation makes spatial relationships harder to understand.

Drone assembly documentation is often presented through static diagrams, part lists and written instructions. Users must mentally reconstruct component orientation, hidden structures and assembly hierarchy.

Static diagrams

Useful for reference, but limited for direct spatial inspection.

Hidden structures

Internal relationships are difficult to infer from 2D views alone.

Cognitive load

Users must translate diagrams into a mental 3D model before acting.

Solution

Interactive technical visualization in the browser.

TwinSight converts CAD-derived drone geometry into a Unity WebGL viewer where users can navigate, select components, activate exploded view, cut through geometry, switch visual modes and read technical information.

Component selection

Select individual drone parts, highlight them and inspect related information in context.

Exploded assembly

Separate assemblies while preserving enough spatial logic to read component hierarchy.

Section cuts

Cut through geometry to inspect hidden structures without losing the whole assembly.

Inspection UI

Use contextual panels for part information, modes and inspection state.

CAD optimization

Turn heavy CAD-derived routes into a WebGL-ready real-time model.

Evaluation

Use SUS, NASA-TLX Raw and Think-Aloud methods for academic formative validation.

Inspection flow

Slow down only where the model needs it.

The key interactions are shown as a sequence: full assembly, isolation, sectioning and technical reading. Each state connects the visual change to an inspection decision.

01

Start from the full assembly

The user lands in a readable drone view instead of a dense CAD scene. Orientation, scale and hierarchy come first.

02

Isolate what matters

Selection, highlight and exploded states make a single component easier to understand without removing it from the system.

03

Look inside the model

Clipping and X-ray-style modes expose hidden structures while keeping the interaction simple enough for a browser workflow.

04

Read the technical layer

UI panels, labels and visual modes connect geometry to inspection decisions instead of acting as decorative effects.

Unity WebGL architecture

Runtime systems, visual states and technical UI.

The Unity application coordinates selection, camera/navigation, exploded-view state, clipping, visual-mode switching, technical metadata and UI Toolkit panels inside a WebGL build.

Interaction controller

Coordinates user input, selected components, camera flow and viewer state.

Visualization states

Switches between realistic, X-ray, ghosted, blueprint, wireframe and thermal-style views.

Technical panels

Connects selected geometry with contextual component information and inspection controls.

Technical art

Visual modes for inspection, not decoration.

The visual modes are framed as technical inspection workflows. The thermal-style mode is explicitly qualitative and not a physics or sensor simulation.

Realistic

Material and form readability.

X-ray

Internal visibility and hidden relationships.

Ghosted

Transparent inspection without losing context.

Blueprint

Technical drawing-style interpretation.

Wireframe

Structure and topology reading.

Thermal-style

Qualitative visual exploration, not simulation.

Thermal-style mode disclaimer

The thermal-style mode is a qualitative visual mode. It is not a physical thermal simulation, FEA result or sensor-driven thermal analysis.

Scope limitations

TwinSight X500 is an academic/portfolio prototype, not a deployed industrial product. It does not include live sensor integration, predictive maintenance, WebAR, multi-user collaboration or production monitoring.
