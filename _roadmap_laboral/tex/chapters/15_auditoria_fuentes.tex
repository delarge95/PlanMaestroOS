\subsection{Hallazgos de auditoria}


\subsubsection{AUD-001 - Work authorization}


\begin{itemize}
\item Severidad: High
\item Hallazgo: El pasaporte portugues no debe presentarse como autorizacion laboral UE actual.
\item Resolucion: Regla canonica: pasaporte/citizenship esperado alrededor de 2028; hasta emision legal, aplicar como Colombia-based remote contractor/B2B.
\end{itemize}


\subsubsection{AUD-002 - Historic data}


\begin{itemize}
\item Severidad: Low
\item Hallazgo: Existen datos historicos como 'July 2026' que contradicen la regla actual.
\item Resolucion: Historic queda fuera del cuerpo del PDF y se indexa como obsoleto; no corrige ni domina los modulos actuales.
\end{itemize}


\subsubsection{AUD-003 - Seniority}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: Aparece 'Senior Technical Artist' en benchmarks, riesgos o textos negativos; no debe convertirse en titulo personal.
\item Resolucion: Usar 'Real-Time 3D Developer / Unity Technical Artist'. Senior solo como benchmark aspiracional o rol a largo plazo.
\end{itemize}


\subsubsection{AUD-004 - TwinSight framing}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: TwinSight puede relacionarse con digital twin, pero no debe presentarse como digital twin industrial completo sin IoT/live state.
\item Resolucion: Framing canonico: Unity WebGL technical visualization, assembly inspection prototype, digital-twin-adjacent.
\end{itemize}


\subsubsection{AUD-005 - AI tooling}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: ARA/AI tooling es ruta secundaria; no debe implicar seniority de AI engineer productivo.
\item Resolucion: ARA se presenta como Python automation / AI tooling prototype, subordinado a TwinSight salvo que se vuelva portfolio-ready.
\end{itemize}


\subsubsection{AUD-006 - Public proof}


\begin{itemize}
\item Severidad: High
\item Hallazgo: GitHub, demo live, CV publico y portfolio son condiciones de credibilidad pendientes hasta que existan URLs reales.
\item Resolucion: Mantener placeholders explicitos y no afirmar disponibilidad publica hasta verificar links.
\end{itemize}


\subsubsection{AUD-007 - Metrics}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: Metricas de TwinSight deben coincidir con tesis final antes de usarse publicamente.
\item Resolucion: Mantener metricas como condicionales si no han sido verificadas contra documento final de tesis.
\end{itemize}


\subsubsection{AUD-008 - Market freshness}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: Empresas, vacantes, salarios y remote policies son datos temporales.
\item Resolucion: El PDF es snapshot; para aplicar se usa tracker vivo y verificacion semanal/top targets.
\end{itemize}


\subsubsection{AUD-009 - Duplicates}


\begin{itemize}
\item Severidad: Low
\item Hallazgo: Hay variantes/duplicados, especialmente 28D y agent\_A4.
\item Resolucion: Se incluyen por trazabilidad, marcados como duplicate/reference; la version complete/canonica manda.
\end{itemize}


\subsubsection{AUD-010 - Legal/tax}


\begin{itemize}
\item Severidad: Medium
\item Hallazgo: Impuestos, contractor setup, residencia y permisos requieren validacion profesional antes de decisiones reales.
\item Resolucion: Tratar los modulos como estrategia informativa; validar con contador/abogado antes de mudanza, facturacion internacional o aceptacion de oferta.
\end{itemize}
