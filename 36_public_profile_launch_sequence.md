# 17. Soft launch vs hard launch

## 17.1 Soft launch

Use if assets are good but not perfect.

```text
portfolio published

LinkedIn Featured updated
no public announcement yet
apply selectively
```

## 17.2 Hard launch

Use when public post is ready.

```text

ArtStation post
demo video public
portfolio fully linked
```

## 17.3 Recommended path

```text
Soft launch first.
Hard launch after QA.
```

Reason:

This allows applications to begin without forcing a public announcement before QA is complete.

```text

```

Then the role/contribution is unclear.


Then limitation wording must be more visible.


Then live demo link must be more prominent.

# 20. Launch failure modes

## 20.1 Failure mode: too academic

Symptom:

```text
people do not understand the value quickly
```

Fix:

```text
move thesis/methodology lower
lead with demo, problem, solution, features
```

## 20.2 Failure mode: too visual, not technical

Symptom:

```text
looks like a 3D render, not a developer/TA project
```

Fix:

```text
add pipeline, architecture, metrics, GitHub, runtime systems
```

## 20.3 Failure mode: overclaiming

Symptom:

```text
interviewers challenge digital twin/AI/thermal claims
```

Fix:

```text
tighten limitations and safe wording
```

## 20.4 Failure mode: broken proof loop

Symptom:

```text
viewer cannot move from LinkedIn to portfolio/GitHub/demo
```

Fix:

```text
cross-link all assets
```
