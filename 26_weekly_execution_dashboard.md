# 26_weekly_execution_dashboard

## Purpose

This document defines the weekly operating system for executing the international job-search strategy.

It explains how to use:

```text
25_application_tracker_template.xlsx
```

and how to make weekly decisions based on evidence instead of mood, anxiety, perfectionism or endless planning.

This is the final operational control layer of the system.

---

# 1. Core operating rule

The job search should now be treated as a measured pipeline.

The weekly question is not:

```text
Do I feel ready?
```

The weekly question is:

```text
What did the data show this week, and what should change next week?
```

The tracker exists to prevent:

- applying randomly;
- forgetting follow-ups;
- over-researching;
- avoiding applications;
- over-polishing the portfolio;
- chasing low-value roles;
- accepting bad offers;
- misreading silence as failure;
- making decisions without evidence.

---

# 2. Weekly review cadence

## Recommended review time

Use one fixed weekly review block:

```text
Sunday evening or Monday morning
Duration: 45–75 minutes
```

Do not review strategy every day. Daily review creates noise.

## Weekly review inputs

Before starting the review, open:

1. `25_application_tracker_template.xlsx`
2. Portfolio / TwinSight case study
3. LinkedIn profile
4. GitHub profile
5. Calendar
6. Notes from interviews or recruiter calls

## Weekly review outputs

At the end of the review, define:

- next week’s application target;
- next week’s outreach target;
- follow-ups due;
- portfolio improvements;
- interview prep focus;
- skill sprint focus;
- red flags;
- one strategic adjustment maximum.

Update these sheets first:


Do not interpret anything until the tracker is updated.

## Step 2 — Check Dashboard

Open the `Dashboard` sheet and check:

- total applications;
- A-priority applications;
- active pipeline;
- interviews started;
- offers;
- follow-ups due;
- average application score;
- average offer score;
- applications by status;
- weekly activity.

## Step 3 — Identify bottleneck

Classify the week into one of these bottlenecks:

| Bottleneck | Meaning |
|---|---|
| Asset bottleneck | Portfolio/CV/GitHub not ready |
| Volume bottleneck | Too few applications/outreach |
| Targeting bottleneck | Applying to wrong companies |
| Positioning bottleneck | Profile not generating replies |
| Conversion bottleneck | Replies but no interviews |
| Interview bottleneck | Interviews but no progress |
| Offer bottleneck | Offers weak or risky |
| Execution bottleneck | Tracker not maintained |

## Step 4 — Choose one correction

Only choose one primary correction per week.

Examples:

- improve TwinSight case study;
- increase A-priority applications;
- rewrite recruiter opener;
- verify top 10 companies;
- practice WebGL interview questions;
- adjust salary response;
- stop applying to C-priority roles.

Do not redesign the whole system weekly.

# 5. Weekly decision thresholds

## Application volume

| Result | Interpretation | Action |
|---|---|---|
| 0–5 applications | Too low | Reduce friction |
| 6–14 applications | Below target | Add scheduled blocks |
| 15–30 applications | Good | Maintain |
| 31–50 applications | High | Check quality |
| 50+ applications | Risk of low quality | Reduce volume |

## Response rate

Use a rolling 2–4 week view, not one week.

| Response rate | Interpretation |
|---:|---|
| 0–2% | Positioning or targeting problem |
| 3–5% | Weak but usable |
| 6–10% | Acceptable |
| 10%+ | Strong for cold applications |

## Interview conversion

| Signal | Interpretation |
|---|---|
| Replies but no interviews | CV/portfolio mismatch |
| Interviews but rejection | Technical/interview gap |
| Tests but no progress | Test execution gap |
| Offers but weak terms | Targeting or negotiation issue |

# 6. Application quality system

## A-priority application checklist

Before sending an A-priority application:

- [ ] Role matches one of the main role families.
- [ ] Remote scope is plausible.
- [ ] Work authorization does not immediately block it.
- [ ] CV variant is correct.
- [ ] TwinSight link is included.
- [ ] Message references company-specific fit.
- [ ] Salary range is not obviously below target.
- [ ] Follow-up date is entered.
- [ ] Tracker row is complete.

## B-priority application checklist

- [ ] Role is adjacent but plausible.
- [ ] Correct CV variant used.
- [ ] Portfolio link included.
- [ ] Follow-up date entered.
- [ ] No major red flags.

## C-priority application checklist

- [ ] Fast application only.
- [ ] No deep customization.
- [ ] Do not spend more than 10 minutes.
- [ ] Use only if volume or cashflow requires it.

# 8. Weekly adjustment rules

## Rule 1 — Do not pivot after one bad week

A bad week is not enough data.

Wait at least:

```text
2–4 weeks
50+ applications/outreach actions
```

before making major positioning changes.

## Rule 2 — Change one variable at a time

Do not change:

- CV;
- headline;
- role target;
- portfolio structure;
- salary range;
- outreach message;

all in the same week.

Change one or two variables, then measure.

## Rule 3 — Preserve the core identity

Every adjustment must preserve:

```text
Real-Time 3D / Unity / Technical Visualization
```

If an adjustment moves away from that, label it as fallback, not strategy.

# 9. Bottleneck diagnosis

## Asset bottleneck

### Symptoms

- avoiding applications because materials are not ready;
- portfolio link not shareable;
- GitHub not clean;
- no TwinSight demo;
- CV still uncertain.

### Fix

Choose one asset and finish it to usable quality.

Priority order:

1. CV.
2. LinkedIn.
3. TwinSight case study.
4. GitHub README.
5. Demo video.
6. Portfolio polish.

Do not improve all assets at once.

---

## Volume bottleneck

### Symptoms

- fewer than 10 applications per week;
- many saved jobs but few sent;
- overcustomization;
- too much research.

### Fix

Use application blocks:

```text
3 blocks/week
90 minutes each
5 applications per block
```

Target:

```text
15 applications/week minimum
```

---

## Targeting bottleneck

### Symptoms

- roles require senior-only experience;
- roles require EU/US authorization;
- roles are pure full-stack;
- roles are pure 3D art;
- roles are low-paid local jobs.

### Fix

Increase proportion of:

- Unity WebGL;
- technical visualization;
- interactive 3D;
- digital twin visualization;
- simulation interfaces;
- product visualization;
- LATAM nearshore contractor roles.

Reduce:

- generic full-stack;
- generic 3D art;
- AAA senior roles;
- EU-only local roles before authorization.

---

## Positioning bottleneck

### Symptoms

- profile views but no replies;
- recruiters misunderstand the profile;
- replies are for unrelated roles;
- people ask “what exactly do you do?”

### Fix

Tighten public wording:

```text
Real-Time 3D Developer / Unity Technical Artist
Unity WebGL
Technical Visualization
CAD-to-Realtime
TwinSight X500
Remote contractor from Colombia
```

Remove distracting emphasis from:

- full-stack;
- AI engineer;
- graphic design;
- generic multimedia;
- unfinished apps.

---

## Conversion bottleneck

### Symptoms

- replies but no interviews;
- recruiters ask for CV then disappear;
- portfolio not opened;
- no technical follow-up.

### Fix

Improve:

- first paragraph of CV;
- TwinSight case study top section;
- demo video;
- GitHub README;
- role-specific application message;
- portfolio card clarity.

---

## Interview bottleneck

### Symptoms

- interviews happen but no next stage;
- weak technical explanations;
- AI questions create discomfort;
- salary discussion feels unstable;
- WebGL/Unity questions expose gaps.

### Fix

Use:

```text
23_interview_answer_bank.md
```

Practice:

- TwinSight 60-second explanation;
- AI-assisted development answer;
- CAD-to-realtime explanation;
- WebGL performance answer;
- salary expectation response;
- contractor-from-Colombia answer.

---

## Offer bottleneck

### Symptoms

- offers too low;
- contracts vague;
- unpaid tests;
- equity-only;
- role too broad;
- full-time contractor with employee-like control.

### Fix

Use:

```text
24_offer_evaluation_scorecard.md
```

Negotiate:

- rate;
- scope;
- paid test;
- payment timing;
- IP terms;
- portfolio permission;
- review after 30/60 days.

Reject if risk remains high.

# 13. Monthly review

Every 4 weeks, do a deeper review.

## Monthly questions

1. Which role family generated the most responses?
2. Which role family generated the best interviews?
3. Which role family generated low-quality offers?
4. Which companies were realistic?
5. Which regions were most responsive?
6. Which job boards were useful?
7. Which outreach message worked best?
8. Which portfolio asset got attention?
9. What technical gap appeared repeatedly?
10. What should be stopped?

## Monthly decision options

| Evidence | Decision |
|---|---|
| Good response from Unity WebGL | Double down |
| Good response from technical visualization | Double down |
| Only full-stack replies | Fix positioning |
| No replies from EU | Deprioritize EU until authorization |
| Low salary LATAM only | Move higher in company tiers |
| Technical interview failures | Skill sprint |
| No interviews after 100 actions | Rewrite CV/portfolio |
| Recruiters confused | Simplify headline/about |

# 15. 60-day gate

At day 60, verify:

| Metric | Target |
|---|---:|
| Applications | 50–90 |
| Outreach actions | 40–80 |
| Recruiter conversations | 3–8 |
| Interview processes | 2–5 |
| Portfolio iterations | 4–8 |
| Skill artifacts | 2–4 |

## If no replies

Likely issue:

- targeting;
- positioning;
- CV;
- portfolio top section.

Do not assume personal failure.

## If replies but no interviews

Likely issue:

- portfolio clarity;
- role mismatch;
- weak proof link;
- CV not specific enough.

## If interviews but no offers

Likely issue:

- technical explanation;
- salary mismatch;
- AI disclosure;
- role seniority mismatch;
- interview preparation.

# 16. 90-day gate

At day 90, choose one:

| Path | Trigger |
|---|---|
| Continue | Interviews/offers active |
| Improve portfolio | Repeated proof gap |
| Increase volume | Low application volume |
| Refine targeting | Wrong roles replying |
| Add fallback | Cashflow pressure |
| Skill sprint | Repeated technical failures |
| Accept offer | Offer meets threshold |
| Reject/pause | Offers risky or dilutive |

## Day-90 decision rule

Use tracker evidence only.

Do not decide based on:

- one rejection;
- mood;
- comparison with other people;
- anxiety about age;
- perfectionism;
- fear of applying;
- dislike of one interview.

# 17. Anti-dispersion rules

## Project freeze

During the active job-search phase, do not start:

- new flagship project;
- new game;
- new app;
- new full-stack product;
- new AI system;
- new portfolio redesign;
- new course path without artifact.

## Allowed work

Allowed:

- TwinSight improvement;
- ARA README/demo cleanup;
- portfolio MVP;
- GitHub cleanup;
- demo video;
- interview prep;
- small skill artifacts;
- targeted company verification.

## Course rule

No course is allowed unless it produces one public artifact.

Examples:

| Course work | Required artifact |
|---|---|
| Unity profiling | before/after note |
| Shader Graph | small visual mode demo |
| Rebelway | FX clip or breakdown |
| German | CEFR checkpoint |
| Python automation | script/demo |
| WebGL | optimization note |

# 18. Response interpretation rules

## Silence

Silence usually means:

- timing;
- volume;
- mismatch;
- ATS filtering;
- hiring freeze;
- role closed;
- not enough proof;
- no referral.

It does not automatically mean the profile is invalid.

## Rejection

A rejection is useful only if categorized:

| Rejection reason | Action |
|---|---|
| Too junior | Add proof / target lower |
| Not authorized | Filter region |
| Not enough Unity | Add Unity proof |
| Not enough WebGL | Add WebGL proof |
| Not enough portfolio | Improve case study |
| Salary mismatch | Adjust target |
| Role filled | Ignore |
| No reason | Track only |

## Positive signal

A positive signal is:

- recruiter asks for CV;
- hiring manager responds;
- portfolio is opened;
- interview scheduled;
- technical question asked;
- request for demo;
- referral offered;
- compensation discussed.

Track all positive signals.
